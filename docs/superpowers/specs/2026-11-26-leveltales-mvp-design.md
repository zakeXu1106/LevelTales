# LevelTales iOS MVP 设计与需求拆解

2026-11-26 · 待确认 · 适用于 `zakeXu1106/LevelTales`

## 1. 产品目标与规格来源

LevelTales 为 4–8 岁孩子提供与英语水平匹配的短篇故事。孩子从定级、选题进入阅读，可以听读、点词、跟读或跳过跟读，再回答三道理解题。家长在独立的授权会话中查看学习进度、调整级别和设置、管理一次买断权益。阅读内容、档案和学习记录保存在设备上。

上传的《LevelTales-MVP 完整 PRD 与功能清单》v1.0 与仓库 [PRD.md](../../../PRD.md) 逐字节一致。按 PRD §6 的 P0 交付，§12 的 T-01–T-28 全部作为发布门槛。F-10.2 周报和 F-11.1 本地计数是 P1。自由文本主题、多孩子档案、账号、同步、广告、社交、自然拼读课程和 Android 在范围之外。美区 $29.99 是待验证的定价假设，实际显示取 StoreKit `Product.displayPrice`。

参考拆解稿提供了离线纵切、幂等回写和隐私边界等候选设计。本文采用当前仓库路径和 [工程结构](../../architecture.md)，并在第 8 节明确列出会改变产品行为或验收的提案。

## 2. 实现路径

| 路径 | 代价与选择 |
| --- | --- |
| 仓库顺序推进，完成阅读后验收离线纵切 | **采用。** 先建立原生启动路径、种子导入和 A1，再接家长门、定级与阅读。上线所用的模板和模型输出从首次接入起就经过校验。 |
| 参考稿的模板纵切优先 | 较早看到阅读体验，但会把现有模板接入放到 A1 之前。保留离线闭环作为第 7 步的里程碑。 |
| 模型优先 | 能提前测出时延和上下文限制，但依赖匹配的 Xcode、真机和分级词表。模型抽测安排在生成管线阶段。 |

当前是独立的 LevelTales 仓库，只有规格和种子内容。首轮编码从 Xcode 工程与 P01/P15 启动路径开始，按仓库 [构建步骤](../../build-steps-and-tests.md) 逐步验收。

## 3. 页面与流程

| 页面 | 行为与边界 |
| --- | --- |
| P01、P15 启动 | iOS 26+，检查 `SystemLanguageModel.default.availability`。PRD 当前口径为不可用进入 P15，无后续流程；SpeechAnalyzer 不可用只影响跟读。已有档案进 P04，新用户进 P03，也可经 P02 手动选级。 |
| P02 家长门 | 长按 2 秒后回答个位数加减题。错题震动并换题，可持续重试。授权只存在内存，5 分钟过期，退后台超过 60 秒过期。进入家长页和执行购买、改级、清档等操作时都检查授权；已进入的页面在授权失效时关闭。 |
| P03 定级 | L2 起测，三种题型，逐题移动难度档位，不重复出题。最多 16 题，提前结束边界见第 8 节。取受测且正确率 ≥70% 的最高级别，无达标级别则 L1。中断或重启丢弃本次答题，完成或门后跳过时建档。 |
| P04–P06 首页、主题、等待 | 置顶继续阅读，显示只读级别徽章。新故事先检查每日时限和额度，主题仅可选随包 12 项。生成等待超过 30 秒切模板；已达限的孩子端显示中性提示，购买入口只有通过家长门才会打开。 |
| P07 阅读 | 每页目标 2–4 句，默认正文 ≥24pt，支持 Dynamic Type，主要控件点击区 ≥56pt。按句朗读，支持单句播放和同步高亮、下划线。前台在末页连续停留 3 秒后记为读完，开放跟读和理解题。 |
| P08–P10 跟读、题目、完成 | 可跳过句子或直接答题。依次呈现细节、词义、理解三道题；答错一次展示原文，第二次答错展示正确答案。完成页回顾本篇新词。 |
| P11/P12/P14 家长 | 报告显示级别进度、本周新词/篇数/时长、最近五篇。可读全文、屏蔽故事、按状态查词、调语速和时限。改级需确认；清档需额外算术验证。晋升需家长确认，L6 到顶。 |
| P13 付费 | 非消耗型 `leveltales.fullaccess`，占位 Bundle ID `app.leveltales`。显示已取得的本地化价格，商品未加载时允许重试。购买成功后回到原流程；额度触发则回 P05。提供恢复购买。 |

孩子端全屏线性导航，无 Tab、价格、购买按钮、设置入口或外链。孩子端以英文和图标为主，家长端中文。购买与恢复由 StoreKit 处理；业务逻辑和素材走本地路径，PCC 是故事生成的可选系统兜底。

## 4. 工程、状态与写入

- 使用 iOS 26.0 部署目标、Swift 6、SwiftUI、SwiftData、Swift Concurrency。一个 App target 和一个 UnitTest target，无第三方包。目录沿用 `App/`、`Models/`、`Seed/`、`Services/`、`Features/`、`Components/`、`Resources/`。一个 App 级路由，`AppState` 管理授权、权益和能力状态。
- View 调用服务和 AppState。仓储封装 ModelContext，管理单档案、故事、词汇、阅读会话、种子版本和权益缓存。纯规则和 Apple 平台调用通过服务协议隔离，测试可以替换时钟、模型、语音和 StoreKit 响应。SwiftData 写入失败时当篇在内存继续，重试复用同一故事或会话 ID；未成功写入的数据无法在进程退出后恢复。
- 种子使用可维护的随包版本号，先完整解码、校验，再一次保存，成功后记录版本。已导入版本跳过，失败允许重试。词库构建累计 lemma 池和词形映射，保留现有 JSON schema；生成词义另存本地缓存，避免扩大分级词汇池。
- 书签保存句索引，大字号重新分页后可找回位置。阅读时长统计前台在阅读器的活跃区间，重读计时；首次完成数按故事去重。开始和完成时间保留供诊断，活动时长支持前后台、跨日和杀进程恢复。词义题写入用会话和题目索引去重，揭晓答案不计答对。
- 生成同一时间只允许一个请求。主题确认时按本地日预留额度，最终模型交付结算，模板、取消和无交付释放。按发起日归属。故事、词汇回写与最终额度记录以同一持久操作保存，UserDefaults 的每日计数可回建。已验证权益以 StoreKit 为准，启动校验并监听交易更新，撤销或退款后重新判定。
- 用固定模板 ID 屏蔽同一模板的后续交付。清档删除档案、故事、学习记录及其本地文件，保留购买权益和随包种子。按日使用账本是否保留见第 8 节。

## 5. 核心链路与失败恢复

### 生成与校验

1. 按当前级别、主题、句型和 A2 候选词组装 T1。到期复习词先取且不超过配额一半，新词按本级词频补齐；候选库存不足时用同级合规模板。端侧用档案小名或 Pip，PCC 使用固定虚构名，PCC 请求字段见第 8 节。
2. 端侧返回结构化标题、3–6 段正文和词表。A1 对正文按小写、缩略展开、形态归一，按词次算超纲率，检查分级长度与目标词不少于两次。正文和标题的黑名单门槛为零，正文超纲率门槛 ≤2%；所有超纲词均有合法替换才做一轮替换，保留标点和大小写后完整复检。正文重新计算实际词汇；模型自报结果只用于诊断。V1–V4 用于独立验证词汇算法，完整故事结构另用满足分级长度的夹具验证。
3. 端侧总计最多两次，PCC 能力可用时一次，最后选择同级未读模板，优先同主题；未读耗尽按最久未读选择。总等待 30 秒；取消或超时后忽略迟到结果。模板随包仍需 A1 校验并通过内容审核；所有可用同级模板缺失、非法或被屏蔽时，显示中性返回提示并释放额度。第 9 步接入理解题后，交付前还需确认本地已有同篇的三题保底组。若模型故事无法组出合规保底题，在结算额度和词汇前改用合规模板；读者进入 P07 之后保持故事和回写不变。
4. T1 注入本级及以下句型。模型上下文不足时按 PRD 改用本级词和低级高频 500 词，校验仍用累计全池。句型和语义安全在设备抽样中人工复核。按 T-09 抽测 L1–L3 100 篇，验收超纲率 ≤2%、黑名单漏检为零、模板兜底率 ≤10%；另测 L6 上下文。插图最多等 8 秒，失败用级别默认插图，文本可读不等插图任务。

### 阅读与学习

- 依次从本地词条、端侧生成释义、仅发音降级。朗读以句 ID 驱动高亮和翻页。末页停留计时在离开末页、退后台或关闭阅读器时取消。
- SpeechAnalyzer 和 SpeechTranscriber 使用 en-US。单句最长 15 秒，音频仅进入内存，完成、取消、拒绝权限和失败均释放。App 不主动下载语音资源；系统语音资源未就绪时禁用跟读或走鼓励路径，孩子仍可进入理解题。A3 在最终转写平均置信度低于 0.55 或不可用时只鼓励；有效转写按词级 LCS 对齐，最多标出前三个未对齐位置。界面无分数和「错误」字样。
- T2 每题四个互异选项和一个正确索引。词义题以本篇目标词和本地释义为准。细节和理解题要求逐字定位证据，并用已审核题组或本地可识别的原句结构验证答案；仅命中证据句而无法验证答案的模型题仍替换。按故事绑定 D6/D8 题组。P07 可读后，端侧 T2 异步尝试改进题目；仅在 P09 打开前且验证通过时替换对应保底题，首次进入 P09 时冻结题组。本地保底检查计入可读时延，T2 推理不计入。
- A2 在故事交付上只回写一次。目标词首见 +1 天，作为复习目标词复现后排 +3、+7 天。三篇不同故事出现且实际答对词义题至少一次转 mastered。报告将已见覆盖率和掌握率分开，两者以当前级别累计池为分母。80% 晋升按 mastered 计算；时限达标拦截新故事，允许继续当篇。

## 6. 种子数据与内容验收

| 项目 | 当前实测 | 完整验收需要 |
| --- | --- | --- |
| D2 词汇 | 210 条，L1 150、L2 60，L3–L6 无新增 | 累计约 1,300 条，包含释义、音标、词形；人工抽检 10%。 |
| D3 句型 | 六级各 10 条 | 审核内容与级别对应，并结合生成样本验收。 |
| D5 定级 | L1/L2 各 6 题，无图片文件 | 六级各至少 20 题与配套图库，题型约 4:3:3。 |
| D6/D8 题组、模板 | 4 篇 L1/L2 模板带题；无独立 D6 文件 | 每级每主题 ≥2 组，共至少 144 组。按 D6 允许独立题组，独立题以可验证题干提供证据，绑定题以模板原句提供证据。两种均可计入内容覆盖，实际替换进故事时仍须符合该篇证据规则。D8 每级 ≥10 篇，覆盖 ≥6 主题。 |
| D7/D9 字表 | 32 同义替换、141 黑名单、43 专有名词、24 缩略、12 主题 | ≥150 对替换、≥200 黑名单、约 50 名词，及主题图标与六级默认插图。 |

静态抽查发现 `tpl-l1-family-01` 正文按英文词计数只有 38 词，低于 L1 的 40 词下限；其他模板也仍需完整 A1 和人工审查。开发测试使用独立、明确标记的夹具，实际儿童交付只使用合规内容。发布检查覆盖结构、引用、资产、重复键和词形冲突、级别数量、证据、A1 及人工内容审核。G4 的 L4–L6 五篇减量与 D8 的六主题下限无法同时满足一篇只归属一主题的 schema，默认仍按每级十篇和六主题交付，申请减量时再定主题下限。

| 步骤 | 工作项 | 完成条件 |

Linux 云环境可编辑源码、校验 JSON 与工程配置，无法运行 `xcodebuild`。首步验收需要安装 iOS 26 SDK 的 macOS/Xcode。模拟器以注入能力和 Stub 验证可替代路径，真机专属用例以 `TODO(real-device)` 标注待验；实测需要支持 Apple Intelligence 的 iOS 设备，交易验收需要 StoreKit 测试配置和沙盒。T-27 用系统模型已就绪的设备切飞行模式，另测语音资源缺失时可跳过跟读。开发方在第 1 步提供 macOS/Xcode 验收，在第 6 步提供支持机型，第 11 步准备商品交易测试；内容方按第 6 节在对应模块的正式验收前提供审核素材。只有首步验收通过才进入第二步。

## 8. 需要确认的开发与产品规则

| 决策 | 建议口径 |
| --- | --- |
| 开工与素材 | 允许用当前仓库和独立夹具开发工程、导入与算法；采用 PRD §8.3 的完整素材指标做发布和完整功能验收。§8.3 原文要求编码前备齐，仓库 AGENTS 明确现有内容为起始集。该处理需纳入设计确认。 |
| 定级早停 | 在 L5/L6 连续同级全对或在 L1 连续同级全错才允许提前结束，以同时满足 T-04/T-05。每级按难度顺序均分低、中、高三档，从 L2 中档开测；答对/错移动相邻档，端点夹紧，目标档用尽取同级最近档未答题。题库不足继续从相邻档最近的未答题选取，候选耗尽则结算。题库顺序用于开发夹具，正式内容由人工提供难度次序。 |
| 免费级别 | PRD 写了买断解锁全部级别，未给出免费级别范围。建议免费用户可在定级所得级别每天生成一次，门后手动调整也可选六级；买断解锁不限次数，付费墙权益据此表述。若选择锁级，要一起确定免费级别和定级超出后的行为。 |
| 启动门槛 | 先按 PRD F-01.1 执行，模型不可用进入 P15。参考稿提议在支持机型但模型暂不可用时允许离线定级和模板阅读，属于需要另定入口和验收的产品变更。 |
| 模型尝试次数 | 依据 A1 和 §14，端侧共两次（首次加一次重试），PCC 再一次。F-04.5 的「最多重生成 2 次」若按额外重试理解会与 A1 冲突。 |
| PCC 与插图 | PCC 仅在 SDK、系统能力、授权以及合规条件满足时启用。仅发送主题、固定虚构角色、词汇和句型；端侧允许用小名。PRD 已规定 iOS 26 的端侧与模板降级。自动图按 F-04.6 设计，参考稿提到的新系统 API 变动需在目标 Xcode SDK 上验证；不可用时沿用随包图，记录对真机验收的影响。 |
| 自然出现与清档 | 已入库的词在不同故事自然出现也计入三篇条件，仅目标复习词推进复习日。清档同时删除派生的儿童学习记录和图片，建议保留当日匿名额度账本，避免通过反复清档重置每日额度。 |
| 兜底题 | 以当前正文证据决定能否使用 D6 题。尚无合适预制题时，建议从原句构造可验证的细节/理解选择题，且词义题由已审核词条构造；若无法组成合规三题，在故事交付前回退至有完整配套题的合规模板。此补充路径仍须通过 T-19/T-20，并保留 D6 发布内容门槛。 |

设计确认后按第 7 节展开文件级实现计划，再开始第 1 步工程编码。
